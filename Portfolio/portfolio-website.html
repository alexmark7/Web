Building this portfolio

I started with three pages and kept adding to them as I learned more HTML, CSS, and JavaScript. I also edited the illustrations in Illustrator. These are the main steps, with screenshots and bits of code from along the way.

Back to projects

Step #01

The first three pages

  • HTML
  • CSS

The first screenshot shows the rough Home page: a grey banner, red links, and a lot of space that I had not worked out yet. I was trying different ways to place links and get the three pages connected.

I used the same stylesheet for all three pages. Home linked to About Me and Interests, and one CSS change could update the look of every page. 

<link rel="stylesheet" href="styling.css">
<a href="about.html"><span>About Me</span></a>
<a href="interests.html"><span>Interests</span></a>

The shared CSS set the same font and page spacing:

.text {
  margin: 0;
  padding: 0px 10vw;
  font-family: Arial, sans-serif;
}

Step #02

Making the navigation stay in place

  • HTML
  • CSS

I replaced the rough banner with a bar that stays at the top while scrolling. Grid gave me a left area for the Portfolio name, a centered area for the links, and the same amount of space on the right. I put repeated text on About Me to test the blur as content passed behind the bar.

The HTML gave the Portfolio name and page links their places in the bar: 

<header class="top-navbar">
  <a class="portfolio-name" href="index.html">Portfolio</a>
  <nav aria-label="Main navigation">
    <a aria-current="page"><span>Home</span></a>
    <a href="about.html"><span>About Me</span></a>
    <a href="interests.html"><span>Interests</span></a>
  </nav>
</header>

This CSS kept the bar in place while the page moved underneath it: 

.top-navbar {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  display: grid;
  grid-template-columns: 1fr auto 1fr;
  backdrop-filter: blur(10px);
}

Step #03

The line under the current page

  • HTML
  • CSS

Next I added a small line under the page you are on. At first the hover effect moved both the text and the line, so I changed it to scale only the span around the text. The line is its own shape below the link, and its bottom value sets the distance from the words. I also kept the active link from reloading the page when clicked.

The link marks the current page, and the span lets me scale just the text: 

<a aria-current="page"><span>Home</span></a>

These CSS rules kept the hover effect on the text and placed the line below it: 

.top-navbar nav a:hover span {
  transform: scale(1.15);
}

.top-navbar nav a[aria-current="page"]::after {
  content: "";
  position: absolute;
  bottom: -29px;
  height: 2px;
}

Step #04

Changing the site into a CV and portfolio

  • HTML
  • CSS

I changed the navigation to Home, Projects, CV, and About Me, and moved the personal introduction onto its own page. The pages share one style.css file, so the navbar, buttons, spacing, and footer stay consistent.

The active page has aria-current="page". It does not need a link to itself, which also stops an unnecessary refresh when clicking the page you are already on. 

<nav aria-label="Main navigation">
  <a href="index.html"><span>Home</span></a>
  <a aria-current="page"><span>Projects</span></a>
  <a href="cv.html"><span>CV</span></a>
  <a href="about-me.html"><span>About Me</span></a>
</nav>

Shared CSS also kept the space above and below each page consistent: 

main {
  min-height: calc(100vh - 170px);
  padding-top: 110px;
  padding-bottom: 60px;
}

Step #05

Putting the CV together

  • HTML
  • CSS

I put coloured skill labels near the top, then split the rest of the CV into clear sections. Each work or education item has its own entry, and I added a button to download the PDF.

I used a time element for the dates, then adjusted the spacing between entries and list items so the page is easier to scan. The VIA education entry is structured like this: 

<div class="cv-entry-heading">
  <h3>Software Engineer Trainee</h3>
  <p><time datetime="2026">2026</time> - Present</p>
</div>
<p class="cv-entry-place">VIA University College</p>

I used Grid to place the main CV entries beside a smaller information box: 

.cv-columns {
  display: grid;
  grid-template-columns: minmax(0, 2fr) minmax(240px, 0.8fr);
  gap: 60px;
}

Step #06

Adding coloured skill labels to the CV

  • HTML
  • CSS

I made the skills at the top of the CV into a list, then gave each item a class for its colour. I used Flexbox to line up the labels and let them wrap when there is less room. I could use the same colours on other pages later.

These are the first two items in the CV skill list:

<ul class="skill-list">
  <li class="skill-html">HTML</li>
  <li class="skill-css">CSS</li>
</ul>

These rules line up the labels and move them onto another row when needed: 

.skill-list {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}

The CSS gives the HTML skill label its colour:

li.skill-html {
  border-color: #e34f26;
  background-color: #170804;
  color: #f06a43;
}

Step #07

Building the Projects page

  • HTML
  • CSS
  • Illustrator

I made a row for each project with a picture, description, technology labels, and a button. Getting the pictures to fit took a few tries: they were too large at first, then looked awkward when the rows were side by side. I settled on one project per row, with a smaller image beside the details on wide screens. I kept the same structure for each project so I can add more without changing the layout.

The technology labels use the same classes I added for the CV:

<ul class="project-skill-list" aria-label="Technologies used">
  <li class="skill-html">HTML</li>
  <li class="skill-css">CSS</li>
  <li class="skill-javascript">JavaScript</li>
  <li class="skill-git">Git</li>
</ul>

Flexbox puts the picture beside the details on wider screens:

.project-box {
  display: flex;
  flex-direction: row;
}

These CSS rules keep the pictures compact without cutting them off: 

.project-box img {
  width: 300px;
  max-width: 32%;
  height: 190px;
  object-fit: contain;
}

I also created SVG illustrations in Illustrator, including the project previews, game pictures, and small icons. I could adjust the artwork visually, then keep it as SVG so it stays sharp when the project pictures change size.

Step #08

A footer with useful links

  • HTML
  • CSS

I added page links, project links, social icons, and contact details to the footer, then worked on balancing the columns. The screenshot captures that spacing work. On smaller screens, the contact details move below the other columns. I kept the project list short in the footer and added a link to the full Projects page.

The footer navigation uses the same page links as the top bar:

<nav class="footer-navigation footer-links" aria-labelledby="footer-navigation-heading">
  <h2 id="footer-navigation-heading">Navigate</h2>
  <a href="index.html">Home</a>
  <a href="projects.html">Projects</a>
  <a href="cv.html">CV</a>
  <a href="about-me.html">About Me</a>

The footer uses one layout on wide screens and another below 950px: 

.footer {
  display: grid;
  grid-template-areas: "info navigation projects socials";
}

@media (max-width: 950px) {
  .footer {
    grid-template-areas:
      "navigation projects socials"

  }
}

Step #09

Reworking the Home page

  • HTML
  • CSS

Home began as a short “Hello and Welcome” page. I moved the longer personal information to About Me and gave Home a clearer introduction, a Projects link, and a CV download. Below that I added the grouped technologies and a small selection of projects, with a link to see the whole list.

The Projects link sits beside the section heading:

<div class="section-heading selected-projects-heading">
  <h2 id="selected-projects-heading">Selected projects</h2>
  <a class="button" href="projects.html">View all projects</a>
</div>

I tried a few fonts and kept a boxier one for the larger headings. The heading size changes with the screen width instead of using one fixed size: 

.home-introduction-text h1 {
  max-width: 900px;
  font-size: clamp(2.5rem, 3vw, 5.5rem);
}

Grid places the skill groups beside each other when there is room: 

.skill-groups {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 28px;
}

Step #10

Fixing the layout at different widths

  • CSS

After adding the Home introduction, coloured skill groups, selected projects, CV, and project rows, I tested the pages in narrower windows. The navigation links needed to stay on one line, while the Home groups and CV skills needed room to stack. Project pictures also needed to move above their text instead of squeezing the description.

I used media queries for these changes rather than making separate mobile pages. The two screenshots show another Home spacing problem: the heading sat too low, then a divider ran behind the buttons after I moved it up. I adjusted the spacing around the introduction and the next section to clear the divider. 

@media (max-width: 768px) {
  .project-box {
    flex-direction: column;
  }

  .project-box img {
    width: 100%;
    max-width: none;
  }
}

On smaller phones, the Home and CV groups become one column, and the navbar has more room: 

@media (max-width: 600px) {
  .portfolio-name {
    display: none;
  }

  .skill-groups,
  .selected-projects-grid,
  .cv-skills {
    grid-template-columns: 1fr;
  }
}

Step #11

Putting it on GitHub Pages

  • Git

I kept the site inside the Portfolio folder with my other school work. GitHub Pages uploads that folder as the site, so its index.html becomes the live Home page. The CSS, JavaScript, images, and PDF all use paths relative to that folder.

This part of the workflow points Pages at the right folder:

- name: Upload the Portfolio folder
  uses: actions/upload-pages-artifact@v4
  with:
    path: "./Portfolio"

Step #12

Handling the navbar and Home scroll

  • CSS
  • JavaScript

The navbar already stayed at the top. I added a small script to show its bottom line only after scrolling starts, then used CSS to fade the line in and out. I also fixed a Home page refresh problem that sometimes returned the browser to the bottom of the page.

The script adds a class when the page is no longer at the top:

function updateNavbar() {
  navbar.classList.toggle("scrolled", window.scrollY > 0);
}

window.addEventListener("scroll", updateNavbar, { passive: true });

CSS makes the bottom line visible when that class is present:

.top-navbar.scrolled {
  border-bottom-color: rgba(235, 235, 235, 0.36);
}

On a Home page reload, this stops the browser restoring the previous scroll position: 

if (navigation && navigation.type === "reload") {
  history.scrollRestoration = "manual";
  window.addEventListener("pageshow", () => {
    window.scrollTo(0, 0);
  }, { once: true });
}

Step #13

Fading between pages

  • CSS
  • JavaScript

I added a short fade when moving to another page. Only the main content and footer fade; the top bar and background stay in place. I also made the underline grow from its middle and stopped that animation from replaying when moving between the Projects list and one of its project pages. That took a few adjustments to get the timing feeling right.

JavaScript starts the fade before following the link:

page.classList.remove("page-ready");
page.classList.add("page-leaving");
window.setTimeout(() => {
  window.location.href = destination.href;
}, fadeTime);

The content class is on the page content and footer, not the top bar: 

.page-transition .content {
  opacity: 0;
  transform: translateY(10px);
  transition:
    opacity 280ms ease-out,
    transform 280ms ease-out;
}

Step #14

Turning the empty background into stars

  • HTML
  • CSS
  • JavaScript
  • AI Tools

I used JavaScript to place small characters in the background on every page. The starting pattern stays the same when I switch pages, while individual stars change brightness or fade away and appear somewhere else. I adjusted their speed, size, colour, and fading until the background felt active without being distracting.

Making the stars move and fill pages of different lengths was above my current JavaScript skill level, so I used AI tools to help build this part. I kept testing the result and changing how often the stars moved and faded.

The background has a place in the HTML behind the page content:

<div class="background" aria-hidden="true">
  <div id="ascii-stars"></div>
</div>

The opacity transition is what stops a star from simply popping on and off: 

.ascii-star {
  opacity: var(--star-opacity, 0.6);
  transition: opacity 550ms ease-in-out;
}

.ascii-star.is-changing {
  opacity: 0;
}

Long pages needed one more fix. Pictures can make the page taller after it opens, so I made the script add stars to the extra space instead of leaving the bottom empty. 

new ResizeObserver(updateStarArea).observe(display);

Step #15

Adding the ASCII UFO

  • CSS
  • JavaScript
  • AI Tools

I added a UFO that appears now and then, moves along a curved path, and starts behind the page content. You can grab it and swing it around. The changing characters turn red while it is held, then fade back at different times after release. The UFO stays in front until they are back to normal, then fades behind the page again.

The curved movement, dragging, and colour changes were also above my current JavaScript skill level. I used AI tools to help write this part, then tried it out and kept adjusting how it moved and looked.

CSS starts the UFO behind the page and brings it forward after a grab: 

.ascii-ufo {
  position: fixed;
  z-index: 0;
}

.ascii-ufo.is-in-front {
  z-index: 1001;
}

JavaScript gives each red character its own time to start fading back: 

changingCharacters.forEach((character) => {
  const timer = window.setTimeout(() => {
    character.classList.remove("is-red");
  }, randomBetween(600, 2000));
  colourTimers.push(timer);
});

Once the last character has faded back, a copy behind the page fades in while the one in front fades out. That makes the UFO move behind the content without suddenly jumping.
