# Portfolio v1.1 cleanup — 12 November 2026

Reports and maintenance files now live inside `portfolio-v1_1`. The website's appearance and page text are preserved. Sixteen unused image files, totaling **5,328,570 bytes**, were removed.

## Layout

| Location | Purpose |
| --- | --- |
| HTML pages, `css/`, `js/`, `files/`, `images/` | The published website: 62 files, including 45 used images |
| `assets/scenery/` | Sixteen current master paintings, all consumed by the image rebuild tool |
| `scripts/optimize-scenery.sh` | The single optional image rebuild tool |
| `reports/` | Performance reports, 19 unchanged raw measurement files, cleanup validation and artwork notes |

The image rebuild script **is not needed to run or serve the website**. It is retained because it rebuilds all 30 current scenery exports from their master paintings. The browser JavaScript under `js/` remains necessary for themes, scenery, navigation and interactions. Shared interaction scripts must also work when their page is reached through navigation from another page.

The Pages workflow now stages only the website files. The previous upload folder was **18,599,122 bytes**; the staged website is **10,232,575 bytes**, about **45% smaller**. Reports, master paintings and maintenance scripts are excluded. This reduces the deployment artifact; it is not a claim that visitors previously downloaded every unused file or that page-load time improved by 45%.

Active source paintings and artwork notes were moved rather than deleted. Local Markdown links were updated; historical raw JSON snapshots were preserved unchanged.
